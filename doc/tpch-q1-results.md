## 7. 分析

### 7.1 Backend 交叉点

- **SF<=0.1**：FS 与 Adaptive 性能基本持平（差距 < 1σ），均远优于 LLVM。
- **SF>=0.3**：Adaptive 明确最优。LLVM 编译来得及切换，Adaptive (17.30ms) 优于 FS (38.16ms) 和 LLVM (25.62ms)。

### 7.2 Adaptive 效果

Adaptive 在所有 SF 下都接近或达到最优：
- 小数据（SF<=0.1）：纯 FS 执行，无 LLVM 编译开销，性能与纯 FS 持平。
- 大数据（SF>=0.3）：FS 先跑 ~63 个 morsel，LLVM 编译完成后切换，总时间优于纯 LLVM。
- SF=10 时 Adaptive (218.6ms) vs LLVM (227.0ms)，Adaptive 快 4%，因为 FS 在 LLVM 编译期间已处理了 63 个 morsel。

### 7.3 Compile vs Execute 占比

| SF | FS compile % | LLVM compile % |
|---:|-------------:|---------------:|
| 0.01 | 7.8% | 71.1% |
| 0.1 | 1.0% | 61.8% |
| 1 | 0.1% | 30.1% |
| 10 | 0.0% | 5.2% |

FS 编译开销始终可忽略。LLVM 在小数据几乎全花在编译上，SF>=10 时编译占比降至 5.2%。

### 7.4 关键发现

1. **FS 与 Adaptive 在小数据完全持平**：SF<=0.1 时两者 execute 差距 < 1σ，确认 adaptive 的 per-morsel 开销可忽略。
2. **FS ns/row 恒定 ~20ns**：与数据量无关，代码质量稳定。
3. **LLVM ns/row ~3.7ns**：比 FS 快 ~5.5x，但固定编译开销 ~12.5ms 使其在小数据不划算。
4. **Adaptive switch point 稳定在 morsel 63**：反映 LLVM 编译时间（~12.5ms）的稳定性。
5. **vs DuckDB 优势随 SF 增大**：1.0x → 6.1x，JIT 执行吞吐远超 DuckDB。

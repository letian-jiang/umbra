## 7. 分析

### 7.1 Backend 交叉点

- **SF<=0.03**：FS 与 Adaptive 性能基本持平（差距 < 1σ），均远优于 LLVM。
- **SF=0.1**：FS (12.40ms) 与 Adaptive (12.42ms) 完全持平，LLVM 编译还来不及完成。
- **SF>=0.3**：Adaptive 明确最优。LLVM 编译来得及切换，Adaptive (17.50ms) 优于 FS (36.23ms) 和 LLVM (24.18ms)。

### 7.2 Adaptive 效果

Adaptive 在所有 SF 下都接近或达到最优：
- 小数据（SF<=0.1）：纯 FS 执行，无 LLVM 编译开销，性能与纯 FS 持平。
- 大数据（SF>=0.3）：FS 先跑 ~65 个 morsel，LLVM 编译完成后切换，总时间优于纯 LLVM。
- SF=10 时 Adaptive (223.2ms) vs LLVM (235.8ms)，Adaptive 快 5%，因为 FS 在 LLVM 编译期间已处理了 65 个 morsel。

### 7.3 Compile vs Execute 占比

| SF | FS compile % | LLVM compile % |
|---:|-------------:|---------------:|
| 0.01 | 10.6% | 96.4% |
| 0.1 | 1.6% | 86.9% |
| 1 | 0.2% | 44.5% |
| 10 | 0.0% | 7.5% |

FS 编译开销始终可忽略。LLVM 在小数据几乎全花在编译上，SF>=10 时编译占比降至 7.5%。

### 7.4 关键发现

1. **FS 与 Adaptive 在小数据完全持平**：SF<=0.1 时两者 execute 差距 < 1σ，确认 adaptive 的 per-morsel 开销可忽略。
2. **FS ns/row 恒定 ~20ns**：与数据量无关，代码质量稳定。
3. **LLVM ns/row ~3.6ns**：比 FS 快 ~5.5x，但固定编译开销 ~17.6ms 使其在小数据不划算。
4. **Adaptive switch point 稳定在 morsel 64-65**：反映 LLVM 编译时间（~17.6ms）的稳定性。
5. **vs DuckDB 优势随 SF 增大**：1.1x → 7.1x，JIT 执行吞吐远超 DuckDB。
